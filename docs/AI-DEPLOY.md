# 给部署 Agent 的执行指南

本文件提供方法，不替用户授权。先读取当前会话中的明确目标及约束；确认用户愿意把含数字短信上传到其自己的服务。不得改用共享第三方短信服务，也不要索取、扫描历史短信作为部署前置条件。

## 必要输入

- 用户自己的 Cloudflare 账户，通过官方登录或最小必要权限的 API Token 使用。
- 同一账户托管的空闲子域名。先检查是否已有 DNS/Worker 绑定，不覆盖已有业务。
- 是否有 Mac、Python 3、Node.js 22+；是否有用户授权的 iPhone 镜像控制能力。

从已有环境和用户会话中获取可查明的信息，只询问真正缺少的输入。仓库示例不包含任何可复用的真实账号或域名。

## 执行顺序

1. 运行 `npm test`。选一个独立 Worker 名称，检查同名资源是否属于本次安装；若名称冲突，换名，不覆盖不明资源。
2. 使用 `npm run setup -- --domain <用户真实子域名> --name <独立名称>` 生成 `.private/`。已有安装必须复用原配置，不能擅自重生成密钥。
3. 通过官方 Wrangler 登录或用户自行提供的环境凭据部署。`npm run deploy` 使用配置与 `--secrets-file` 一同上传代码和两项密钥。核对自定义域名 HTTPS 可用。
4. 运行 `npm run verify`：检查健康状态、未授权读取失败、合成内容上传、读回、去重及到期后不可见。工具无部署权限时准备好结果和错误摘要，只暂停部署步骤。
5. 执行 `npm run shortcut`，按 `docs/IPHONE.md` 生成、签名、导入或手工配置上传指令。不得公开上传生成文件；其中包含上传密钥。
6. 经用户授权，可操作 iPhone 镜像建立 0–9 十条立即运行自动化。没有手机控制能力时给出步骤，不能虚报已配置。不能通过私有系统数据库强改个人自动化，也不要把普通字符串匹配声称为正则触发。
7. 让用户从另一部手机发送一条测试短信，处理预期的首次联网权限，验证私人 JSON 返回新记录。区分“已生成文件”“已配置设备”“合成请求通过”“真实收信通过”。
8. 如果用户要求静默，按手机实际提供的选项处理。全局关闭快捷指令通知会影响其他快捷指令，应先说明范围；不要替用户削弱其他系统保护。
9. 把私人接入说明保留在 `.private/agent-access.md`，告诉用户文件位置和用法。不要在聊天或命令输出中打印凭据、带读取密钥的 URL、短信全文或验证码。仅用“收到新记录/测试通过”等必要元数据报告。

## 完成标准

必须验证权限隔离、十分钟窗口、重复不续期和真实手机触发。只有用户暂时无法发测试短信时，才能明确交付为“部署配置完成，真实收信尚待验证”。不得靠请求一个真实登录验证码到外部账号来代替用户测试。

## 回滚

先关闭这十条个人自动化，再移除本次 Worker 的自定义域名。确认资源范围后再删除本次独立 Worker，避免影响其他应用。删除存储数据前遵守用户与平台的确认要求。撤销临时部署凭据不等于停用正在运行的 Worker。
