# 从想法到可复现系统

需求是让线上 Agent 在用户授权的登录任务中读取手机上的新验证码。iPhone 上普通 App 无法像桌面程序一样随意监听全部短信，因此采用系统“收到信息”个人自动化。

最初容易把重点放在识别规则：四位、六位、八位，或数字加字母。但严格识别会漏掉平台格式变化，而本系统只保留很短的读取窗口。因此将两件事分开：手机尽量宽地触发并上传原文，后端给出候选，Agent 结合平台和申请时间判断。

手机的触发器使用文字“包含”，不是正则引擎。为覆盖任意数字，用 `0` 到 `9` 十条小规则，所有规则调用同一个上传快捷指令。某条短信命中多个规则产生重复请求，所以后端以正文和发件人去重，并保留第一次的展示截止时间。

后端是一个 Worker 和一个 Durable Object。Worker 管理授权、输入和输出；Durable Object 串行保存、筛选、去重和清理短信。上传和读取分离，避免把放在手机里的上传凭据直接当作短信读取凭据。

十分钟窗口由服务器每次读取时检查，不能只依赖网页倒计时或延迟清理。清理定时器负责收拾存储，而读取过滤负责保证到期后不返回。云服务备份和底层保留策略与业务接口可见性是不同概念，不能承诺所有副本十分钟内物理擦除。

页面不需要做复杂。JSON 本身携带使用说明、时间、候选和原文，足够具备联网能力的 Agent 使用。需要肉眼查看时提供同样信息的简单页面。

验证分两层：合成请求验证后端权限、持久化、去重和过期；真实新短信验证 iPhone 触发、首次联网授权及实际输入传递。前者成功不能代替后者。运行提醒属于 iOS 系统通知设置，不能靠服务器或在快捷指令中不写“显示通知”来保证消失。

复用时最重要的不是复制某个人的已签名文件或域名，而是为每个安装生成自己的密钥、绑定自己的域名、在自己的手机上完成权限和触发测试。
